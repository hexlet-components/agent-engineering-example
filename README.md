# Триаж входящих тикетов на OpenAI Agents SDK

Автор T-42 получил пустой CSV при экспорте. Агент читает обращение в учебном трекере и предлагает следующий шаг. Номер похожего тикета помогает найти сведения, а решение о повторе или завершении принимает приложение. Реализации на Python и TypeScript используют одни и те же тикеты, инструкции и подготовленные ответы модели.

## Первый запуск

Склонируйте репозиторий и перейдите в его каталог. Для Python понадобятся Python 3.14 и uv, для TypeScript нужны Node.js 26 и pnpm. Версии указаны в _mise.toml_ и _package.json_. Выберите один язык.

```sh
make setup AGENT_LANG=python
make demo AGENT_LANG=python
```

```sh
make setup AGENT_LANG=typescript
make demo AGENT_LANG=typescript
```

По умолчанию запускается сценарий агентного цикла. В первой записи `trace` модель запрашивает `read_ticket` для T-42. Следующая запись содержит ответ трекера с тем же `call_id`. В списке `decisions` видно, какое предложение получила программа и приняла ли она его. Полный вывод сохраняется в _var/python.json_ или _var/typescript.json_.

В режиме `demo` ключ API не нужен. Подготовленные ответы поступают от подмены модели, а цикл SDK, инструменты и приёмка выполняются при каждом запуске.

## Сценарии уроков

Передайте название урока через `SCENARIO`, например `make demo SCENARIO=verification AGENT_LANG=python`. Каждый сценарий запускается отдельно с исходными данными трекера.

| Сценарий | Что сравнить в выводе |
| --- | --- |
| `agent-loop` | Запрос одного инструмента, его результат и решение |
| `tool-contracts` | Совпадения, пустая выдача и отказ поиска |
| `agent-instructions` | Ответы по тикету до и после уточнения о фильтре |
| `trust-boundaries` | Одинаковая просьба изменить метку при двух наборах полномочий |
| `source-discovery` | Описание T-42 и условие воспроизведения в T-17 |
| `context-budget` | Полное обсуждение и выдержки со ссылками для следующего хода |
| `task-state` | Сохранённый вопрос Q-42, ответ автора и возобновление задачи |
| `mcp` | Объявление инструмента отдельным сервером и результат чтения |
| `verification` | Повтор после ссылки на непрочитанный источник, приёмка и исчерпание попыток |
| `trajectories` | События двух чтений и основания итогового ответа |

Для MCP обе реализации запускают один локальный сервер на Python через стандартные потоки. Перед этим сценарием на TypeScript выполните `make setup-all`. В сценарии паузы приложение записывает ожидающий запрос во временный файл, читает его при доставке учебного ответа и сохраняет оба состояния в выводе.

## Код и тесты

Начните с _fixture/tickets.json_. Контракты инструментов, настройки агента и проверка результата находятся в _python/agent_example/agent.py_ и _typescript/src/agent.ts_. Обработчики учебного трекера лежат в _workspace.py_ и _workspace.ts_. Тесты прогоняют сценарии через SDK и проверяют решения о повторе, сопоставление запросов с результатами и отказ в изменении метки.

```sh
make setup-all
make check
```

Чтобы выполнить только проверку двух чтений на выбранном языке, запустите `make test-trajectory AGENT_LANG=python` или `make test-trajectory AGENT_LANG=typescript`. Достаточно зависимостей соответствующего клиента.

## Запуск с моделью

Скопируйте _.env.example_ в _.env_ и задайте `MODEL_ID` и `OPENAI_API_KEY`. Выберите модель с поддержкой инструментов и структурированного ответа. Затем выполните `make run SCENARIO=source-discovery AGENT_LANG=python` или замените язык на `typescript`. Для совместимого Chat Completions API пример читает также `MODEL_API=chat_completions`, `MODEL_BASE_URL` и `MODEL_API_KEY`.

Модель сама выбирает запросы и может пройти по иному пути. Приложение проверяет, что агент прочитал тикеты, на которые сослался. Оценка того, объясняют ли эти сведения предложенный шаг, остаётся за читателем.
