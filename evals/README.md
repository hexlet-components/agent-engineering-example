# Оценка агента триажа

В этом примере Promptfoo запускает готового агента на OpenAI Agents SDK. Агент читает обращения в учебном трекере, предлагает дубликат или задаёт вопрос и может поставить метку `needs-info`. Инструменты работают в памяти. Новая попытка получает пустой набор меток. Все файлы для курса находятся в каталоге _evals_.

## Первый прогон

Понадобятся Git, Node.js 24 или новее и npm. Учебная модель проведёт две попытки по заданному сценарию.

```bash
git clone https://github.com/hexlet-components/agent-engineering-example.git
cd agent-engineering-example/evals
npm ci
TRIAGE_BACKEND=demo npm run first
```

В _var/first.json_ откройте `results.results` и найдите строку с `vars.id`, равным T-42. Поле `response.output` содержит ответ, метки после запуска и вызовы инструментов. Оценка попытки лежит в `success`. Чтобы проверить другой критерий на тех же данных, измените выражение `assert[0].value` для T-42 в _first.json_ и выполните `npm run replay`. Например, требование `output.answer.duplicate === 'T-17'` отклонит сохранённый вопрос о фильтре. Верните исходное выражение и повторите команду.

## Прогоны с моделью

Для OpenAI задайте `OPENAI_API_KEY` в окружении. Через `OPENAI_MODEL` и `JUDGE_MODEL` можно выбрать модель агента и судьи. По умолчанию используется `gpt-4.1-mini`. Для оценки затрат задайте цену миллиона входных и выходных токенов в `INPUT_USD_PER_M` и `OUTPUT_USD_PER_M`. Это расчёт по плоскому тарифу. Если цена неизвестна, отчёт сохраняет `null`.

Можно использовать локальный сервер с интерфейсом OpenAI Chat Completions. Модель должна поддерживать вызовы инструментов и вывод JSON. Укажите имя обслуживаемой модели и порт сервера на своей машине.

```bash
export TRIAGE_BACKEND=local
export LOCAL_MODEL=default_model
export LOCAL_MODEL_PORT=8080
npm run first
```

| Команда из каталога _evals_ | Что посмотреть |
| --- | --- |
| `npm run metrics` | Число верных, лишних и пропущенных пар, точность и полноту предложений на рабочих тикетах |
| `npm run calibrate` | Ошибки двух редакций рубрики на рабочих ответах и ошибки уточнённой рубрики на отдельной разметке |
| `npm run compare` | Три свежие попытки каждой версии на каждом рабочем тикете |
| `npm run release` | Парное сравнение на отложенных обращениях после записи условий выпуска |
| `npm run regression` | Проверку кандидата на освоенных задачах из _regression.json_ |
| `npm run regression:expanded` | Отказ проверки на сохранённой ошибке из _incident.json_ и новый прогон прежних тикетов вместе с T-90 |

Перед `release` запишите минимальный прирост качества, недопустимые регрессии и бюджеты. До этой записи разбирайте только рабочие тикеты T-42, T-43, T-44 и T-45. Судья получает рубрику, исходное обращение и текст вопроса. Ручное решение из _calibration.json_ используется после оценки для подсчёта расхождений.

Каждая команда сохраняет конфигурацию Promptfoo и отчёт в _var/_. Для калибровки имена файлов указывают редакцию рубрики и группу ответов. Повтор команды перезаписывает её отчёт. Чтобы сопоставить несколько прогонов, сохраните копию. У каждой оценки можно прочитать отдельные проверки и их обоснование в `gradingResult.componentResults`. Содержательность вопроса при сравнении версий оценивает читатель по тексту тикета и вопроса. Автоматические проверки на этом этапе учитывают предложенную связь, метку и наличие текста вопроса там, где он нужен.
