# Ревью экспорта заказов

Публичная выгрузка принимает до 100 заказов. Для внутренней сверки нужны все заказы. В политике сервиса срок хранения задан в секундах, а хранилище принимает миллисекунды. Сравните несколько ревьюеров на изменениях одного сервиса. Для запуска понадобятся Git и Node.js 26. Команды выполняйте из каталога репозитория.

```sh
node code-review/run.ts review orders-v1 baseline
node code-review/run.ts review internal lookup
node code-review/run.ts review clean baseline
```

Обработчик восстанавливает учебный Git-репозиторий во временном каталоге, вычисляет общий предок веток, читает дифф и передаёт выбранные файлы исполнителю. Поле `initial` содержит первый черновик, `candidates` включает находки повторных проходов, `published` показывает комментарии для автора. Откройте [сохранённый первый прогон](data/baseline-orders-v1.json) и найдите строку дефекта в диффе.

Исполнитель на TypeScript имитирует ответы модели по тексту выбранных файлов и направлению проверки. Например, общий ревьюер замечает ошибку с единицами времени, если первым прочитал контракт хранилища. Это заданное поведение позволяет повторить опыт с порядком файлов. При повторном запуске меняется время работы. Внешние сервисы в опыте не участвуют. Обсуждения и история Git подготовлены для курса.

## Сравнение на рабочем наборе

Команда `node code-review/run.ts compare work` запускает варианты на двух версиях публичного экспорта, внутренней сверке и корректной публичной выгрузке. Отдельную версию можно разобрать командой `node code-review/run.ts review orders-v1 files`, подставив нужную схему из таблицы.

| Схемы | Что меняется |
| --- | --- |
| `baseline`, `context`, `lookup` | Общий ревьюер получает изменённые файлы. Во второй схеме он сразу читает правило об исключении. В третьей запрашивает его, когда заподозрил превышение лимита. |
| `specialists`, `routed` | Четыре специалиста получают одно изменение. Маршрутизатор вызывает специалиста по безопасности при изменении каталога авторизации. |
| `whole`, `files`, `linked` | Те же применимые направления получают весь набор изменённых файлов, по одному файлу или набор с импортами. |
| `partial` | Имитируется сбой чтения файла хранилища. Журнал отличает отказ от пропуска файла при выборе области проверки. |
| `verified`, `consensus` | Первая схема проверяет каждого кандидата по коду и правилам. Вторая требует совпадения двух проходов с разным порядком файлов и перепроверяет оставшиеся находки. |
| `critic`, `filtered` | Критик читает черновик целиком и берётся за единицы времени, если они ещё не проверены. Фильтр в отдельном опыте получает замечания специалистов, объединяет повторы и оставляет высокую серьёзность. |

В _data/labels.json_ размечены место и смысл каждого ожидаемого замечания. Оценщик считает уникальные совпадения по пути, строке и категории. Ложные замечания и дубли учитываются отдельно. Проверьте разметку через наблюдаемое поведение. Команда `node code-review/oracle.ts work` исполняет код каждой версии на 101 заказе и сверяет количество записей и срок хранения с контрактом. Она распаковывает и запускает только подготовленные исходники этого примера.

## Новая версия и обратная связь

```sh
node code-review/run.ts update orders-v1 orders-v2
node code-review/run.ts update orders-v1 orders-v2 orders-v1
node code-review/run.ts feedback
node code-review/oracle.ts transfer
```

Первая команда проверяет новые коммиты вместе с импортами и сравнивает находки с полным проходом. В данном корпусе в одном файле встречается не больше одного дефекта каждого типа. Поэтому для сопоставления обсуждений между версиями достаточно пути и категории. Исправленный лимит закрывает старое обсуждение. Ошибка со сроком сохраняет обсуждение и получает новую строку. Третий аргумент второй команды имитирует расхождение текущей и проверенной ревизий перед публикацией.

В журнале обсуждений автор отклоняет требование ограничить внутреннюю выгрузку. В другом PR человек первым замечает ошибку в сроке хранения. Команда `feedback` показывает оба сообщения и извлекает из ответа автора исключение для внутреннего файла. На двух новых рабочих PR она сравнивает исходный вариант с узким правилом и с подавлением всех замечаний о лимите. Пропуск, который заметил человек, можно проверить независимо через `oracle.ts`.

## Итоговый прогон

Перед проверкой на трёх отложенных PR мы выбрали четыре схемы по [рабочему прогону](data/work-results.json). В коммите `0415e56` сохранены настройки, версии исполнителя и оценщика, история изменений и разметка. Команда проверяет контрольные суммы и прекращает расчёт, если содержимое изменилось. [Зафиксированные настройки](data/frozen.json).

```sh
node code-review/run.ts compare holdout
node code-review/oracle.ts holdout
```

В [результатах первого прогона](data/holdout-results.json) критик нашёл два из трёх дефектов за шесть обращений к исполнителю. Перепроверка каждого кандидата нашла те же два дефекта за двадцать обращений и пропустила к автору повтор. Все четыре схемы пропустили ошибочное ограничение в 101 заказ. Обращения локальные, стоимость API равна нулю. Поле `localMs` содержит сумму длительностей работы ревьюера на одном проходе по набору. Подготовка истории и оценка находок в это время не входят. Для оценки цены и задержки развёрнутой системы понадобится замер с её моделью.

## Опыт с моделью

На рабочей версии `orders-v1` мы отдельно вызвали модель `gpt-6.2-astra` через Codex CLI 0.172.0 с усилием рассуждения `medium`. В первом проходе модель видела дифф и заметила ошибку в сроке хранения. Критик получил её черновик, код и правило экспорта. Он добавил пропущенное ограничение в 100 заказов. Контрольный проход с теми же кодом и правилом сразу нашёл оба дефекта. На этом PR одного добавления контекста хватило для обеих находок. В каждом условии был один вызов, инструменты модель не вызывала. [Запросы и ответы](live).

Чтобы повторить отдельный вызов с теми же входными данными, передайте сохранённый запрос установленной и авторизованной Codex CLI. Начинайте каждый вызов в новом сеансе. Для критика подставьте _critic.txt_, для контрольного прохода возьмите _control.txt_. Запрос критика уже включает исходный ответ первого прохода.

```sh
codex exec --ephemeral --sandbox read-only -m gpt-6.2-astra -c 'model_reasoning_effort="medium"' - < code-review/live/first.txt
```
